# Bölüm 2.6: Kontrol Soruları ve Çözüm Notları

### 1. `list` yerine `collections.deque` ne zaman kullanılır?

* **Senaryo:** FIFO (First-In, First-Out) kuyruk mimarileri, kayan pencere (sliding window) algoritmaları ve sabit boyutlu log arabellekleri.
* **Gerekçe:** 
  * Python'daki `list` dinamik bir dizidir. Listenin başına eleman eklemek (`list.insert(0, x)`) ya da başından eleman çıkarmak (`list.pop(0)`), arkasındaki tüm N elemanın bellekte kaydırılmasını gerektirdiği için O(N) maliyet üretir.
  * `collections.deque` çift yönlü bağlı blok listesidir. Başa veya sona ekleme/çıkarma işlemleri işaretçi seviyesinde yapılır ve her zaman O(1) zaman karmaşıklığındadır. Ayrıca `maxlen=K` parametresiyle bellek sızıntısını engelleyen sabit boyutlu kuyruklar kurulabilir.

### 2. Bir decorator'da `functools.wraps` kullanılmazsa ne kaybedilir?

* **Metaveri Kaybı:** Dekore edilen asıl fonksiyonun `__name__`, `__doc__`, `__annotations__` ve `__module__` bilgileri silinir; yerine wrapper fonksiyonun adı ve boş docstring'i geçer.
* **Debugging ve Loglama:** Traceback ve Sentry gibi izleme araçlarında asıl hata veren fonksiyonun ismi kaybolur.
* **Introspection Kırılması:** `inspect.signature` çalışmaz; FastAPI, Typer gibi fonksiyon imzasından parametre ve tip çıkaran modern framework'ler patlar.
* **Saf Fonksiyona Erişim:** Test yazarken dekoratörü bypass edip saf fonksiyona ulaşmayı sağlayan `fn.__wrapped__` referansı oluşmaz.

### 3. Protocol ile ABC Arasındaki Fark

* **ABC (Nominal Typing / Açık Kalıtım):** Sınıfın abstract sınıftan açıkça türemesi (`class CsvSink(Sink):`) şarttır. Runtime'da `isinstance` kontrollerine dayanır ve sınıflar arasında sıkı bağımlılık (tight coupling) yaratır.
* **Protocol (Structural Subtyping / Statik Duck Typing):** Sınıfın herhangi bir sınıftan kalıtım almasına gerek yoktur. Sınıf, Protocol'de tanımlanan metodun imzasını taşıyorsa `mypy` tarafından geçerli kabul edilir. Kütüphane bağımsızlığı ve gevşek bağlılık (loose coupling) sağlar.

```python
from abc import ABC, abstractmethod
from typing import Protocol

# ABC Yaklaşımı (Nominal)
class BaseSink(ABC):
    @abstractmethod
    def write(self, record: dict) -> None: ...

class SqlSink(BaseSink):  # Açıkça kalıtım almak ZORUNDA
    def write(self, record: dict) -> None:
        pass

# Protocol Yaklaşımı (Structural)
class SinkProto(Protocol):
    def write(self, record: dict) -> None: ...

class CustomSink:  # Kalıtım yok, sadece metot imzası eşleşiyor
    def write(self, record: dict) -> None:
        pass

def export(s: SinkProto) -> None:
    s.write({"status": "ok"})

export(CustomSink())  # Mypy strict modunda hatasız geçer
```

### 4. 100 GB'lık CSV'yi 8 GB RAM'de İşleme Stratejileri

1. **Generator Tabanlı Streaming (Stdlib / Chunked I/O):**
   Dosyayı satır satır veya sabit boyutlu bloklar (`chunksize=100_000`) halinde diskten okuyup işleyerek doğrudan hedefe yazmak. RAM tüketimi dosya boyutundan bağımsız olarak sabit (~50–200 MB) kalır.
2. **Polars / DuckDB Lazy Streaming:**
   `pl.scan_csv("data.csv").filter(...).collect(engine="streaming")` veya DuckDB SQL motoru ile bellek haritalama (mmap) ve disk tabanlı arabellek (spill-to-disk) kullanarak paralel sorgu işletmek.
3. **Parquet Dönüşümü & Kolon Tabanlı Okuma (Chunked Arrow Conversion):**
   CSV dosyasını parça parça Arrow/Parquet formatına dönüştürüp yalnızca analizde gereken kolonları (`use_columns`) ve satır gruplarını (row group) belleğe alarak 10x bellek sıkıştırması sağlamak.

### 5. `pytest` Fixture `scope` Parametresi ve Veritabanı Testi Stratejisi

Fixture'ın yaşam döngüsünü (ne sıklıkla oluşturulup yok edileceğini) belirler:
* `function` (varsayılan): Her test fonksiyonu için baştan çalıştırılır.
* `class`: Her test sınıfı için bir kez çalıştırılır.
* `module`: Test dosyası (.py) başına bir kez çalıştırılır.
* `session`: Tüm test paketi boyunca sadece bir kez çalıştırılır.

**Veritabanı Testlerinde Seçim:**
* **`session` Scope:** Veritabanı bağlantı havuzu (`engine`) ve test container'ı (Postgres Docker container) ayağa kaldırmak için seçilir. Her testte container kurma maliyeti elenir.
* **`function` Scope:** Her test için izole transaction (`db_session`) başlatılır. Test bittiğinde `ROLLBACK` yapılarak veritabanı temizlenir ve testlerin birbirinden izole kalması sağlanır.
