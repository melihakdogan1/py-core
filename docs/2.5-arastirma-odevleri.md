# Bölüm 2.5: Araştırma Notları

## 1. GIL (Global Interpreter Lock) İncelemesi

CPython'ın bellek yönetimindeki reference counting mekanizmasını thread-safe tutabilmek için kullandığı global kilit mekanizmasıdır. Temel kural basit: Aynı anda tek bir CPU çekirdeğinde yalnızca tek bir işletim sistemi thread'i Python bytecode'u çalıştırabilir.

### Ne zaman darboğaz yaratır? (CPU-Bound)
Ağır matematiksel hesaplamalar, döngüsel veri dönüşümleri veya matris işlemleri gibi CPU'yu kilitleyen senaryolarda `threading` modülü paralel hızlanma sağlamaz. Aksine, thread'ler GIL kilidini kapabilmek için sürekli context-switch maliyeti üretir ve çoklu thread tek thread'den bile yavaş kalır.
* **Nasıl aşıyorum:** Bu tip işlerde doğrudan `multiprocessing` (ayrı bellek alanına sahip izole alt süreçler) veya GIL kilidini C/Rust seviyesinde serbest bırakan extension'lar kullanıyorum.

### Ne zaman sorun olmaz? (I/O-Bound)
Ağ istekleri (`httpx`, `requests`), disk okuma/yazma veya veritabanı sorgularında Python, I/O beklerken GIL'i otomatik bırakır. Bir thread ağ cevabını beklerken CPU diğer thread'e geçer. Ayrıca Polars ve NumPy gibi kütüphaneler hesaplama anında GIL'i bypass edip tüm çekirdekleri C/Rust düzeyinde vektörize olarak çalıştırabilir.

## 2. Veri İşleme Kodlarında Test Stratejisi

Veri pipeline'larında sadece standart happy-path birim testleri yazmak prod ortamında patlamaya davetiye çıkarır. Kodun doğruluğunu 4 ana katmanda güvenceye alıyorum:

1. **Şema Doğrulama (Schema Validation):** Pipeline'a giren ve çıkan verinin tiplerini, zorunlu alanlarını ve null durumlarını statik seviyede Protocol/Pydantic, dinamik tablolarda ise Pandera ile doğrulayıp şema kaymalarını (schema drift) runtime başında kesiyorum.
2. **Değişmezlik (Invariant) Testleri:** Veri dönüşümü boyunca korunması zorunlu matematiksel kurallardır. Filtreleme sonrası satır sayısının asla girdi sayısını geçememesi (`len(out) <= len(in)`) veya aggregation adımlarında toplam tutarların eşitliği gibi.
3. **Altın Dosya (Golden File / Snapshot) Testleri:** Karmaşık dönüşüm zincirlerine sabit bir girdi verip, üretilen çıktıyı daha önceden doğrulanmış referans çıktı dosyasıyla bit-by-bit kıyaslayarak regresyonları yakalıyorum.
4. **Property-Based Testler (`Hypothesis`):** Uç durumları (boş string, unicode bozulmaları, negatif sayılar, aşırı büyük integer'lar) manuel yazmak yerine Hypothesis'e rastgele ürettirip pipeline'ın hiçbir girdi varyasyonunda çökmediğini ve invariant'larını koruduğunu matematiksel olarak test ediyorum.
